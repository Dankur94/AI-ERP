# Was ist eine API auf Programmiersprachen-Ebene

## In einem Satz

Eine API ist eine **Funktion die man von aussen aufrufen kann** — mit klarem Input und Output.

---

## Auf Code-Ebene

Eine API ist nur das:

```python
# OHNE API (nur intern nutzbar):
def berechne_preis(produkt, menge):
    return produkt.preis * menge


# MIT API (von aussen aufrufbar):
@app.post("/api/preis")
def preis_berechnen(produkt_id: str, menge: int):
    produkt = db.get(produkt_id)
    return {"preis": produkt.preis * menge}
```

Der Unterschied: Die zweite Funktion hat eine **Adresse** (URL) die jemand ueber das Internet aufrufen kann.

---

## Was passiert technisch

```
Mary tippt auf "Buchen"
       |
       | Handy schickt ueber Internet:
       | POST https://unsere-app.com/api/bookings
       | Body: {"shop": "tonys", "time": "14:00"}
       |
       v
Unser Server empfaengt das
       |
       | Python-Code wird ausgefuehrt:
       | @app.post("/api/bookings")
       | def create_booking(shop: str, time: str):
       |     ...Code laeuft...
       |     return {"status": "ok", "id": "BK-42"}
       |
       v
Antwort geht zurueck an Marys Handy
       |
       v
Mary sieht: "Termin bestaetigt"
```

---

## API = Vertrag

Eine API ist ein Vertrag zwischen zwei Seiten:

```
"Wenn du mir DAS schickst..."     →  "...bekommst du DAS zurueck."

Input: {shop: "tonys", time: "14:00"}
Output: {status: "ok", id: "BK-42"}
```

Wer den Input schickt ist egal: Handy, Browser, WhatsApp-Bot, anderer Server.
Solange der Input stimmt, kommt die richtige Antwort.

---

## Verschiedene API-Arten

| Art | Wie es funktioniert | Beispiel |
|---|---|---|
| REST API | URL + HTTP-Methode (GET, POST, DELETE) | `POST /api/bookings` |
| GraphQL | Eine URL, du fragst was du willst | `query { booking(id: 42) { time, shop } }` |
| WebSocket | Dauerhafte Verbindung, Echtzeit | Chat, Live-Updates |
| Interne API | Funktion im Code, nicht ueber Internet | `booking_service.create(...)` |

Wir nutzen **REST API** — der Standard, den jeder kennt und Claude perfekt beherrscht.

---

## Warum "API + Server = Gold"

Weil die API das Einzige ist was zaehlt:
- Web-App kann kaputt gehen → neu bauen, API bleibt
- Android-App wird irrelevant → egal, API bleibt
- Neuer Client (WhatsApp-Bot) → baut auf dieselbe API
- T1-Entwickler will eigene App → nutzt dieselbe API

Die API ist permanent. Alles andere ist austauschbare Huelle.
