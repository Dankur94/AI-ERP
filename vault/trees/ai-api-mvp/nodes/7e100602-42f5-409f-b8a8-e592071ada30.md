# T1 Developer Portal & Docs

## Was der Entwickler braucht

- API-Dokumentation (OpenAPI/Swagger)
- API-Key Verwaltung
- Sandbox zum Testen
- Verbrauchs-Dashboard (Kosten, Rate Limits)
- Beispiel-Code (Python, Node.js)
- Webhook-Konfiguration
- SDK-Package (`pip install superapp-sdk` / `npm install @superapp/sdk`)

## Modul-Registry (von OpenClaw OC15 — ClawHub)

OpenClaw hat eine zentrale **Skill-Registry (ClawHub)** wo Entwickler Skills finden und installieren koennen. Fuer uns spaeter:

- T1-Entwickler publishen Module in unsere Registry
- Andere T2-Laeden koennen Module aus der Registry aktivieren
- Review-Prozess bevor ein Modul live geht
- Bewertungen + Installationszahlen sichtbar

Das ist der **Modul-Marktplatz** — aber erst ab 50+ T1-Entwicklern relevant.

## Plugin-Manifest (von OpenClaw OC11)

Jedes T1-Modul liefert ein `manifest.yaml`:
```yaml
name: booking-extended
version: 1.0.0
author: developer@example.com
permissions:
  data: [bookings, customers]
  endpoints: [POST /bookings, GET /bookings/:id]
  webhooks: [https://partner.example/notify]
  queue: booking
hooks:
  on_booking_created: handle_new_booking
  on_payment_received: confirm_booking
```

Das Gateway liest das Manifest und registriert das Modul automatisch.

## Anforderungen

- Docs muessen klar und vollstaendig sein
- "Hello World" in unter 5 Minuten
- Fehler muessen verstaendliche Messages haben
- Sandbox = echte API, aber mit Test-Daten (Deny-by-Default, NC1)

## Prioritaet
