# Sicherheit & Standards — Technische Umsetzung

## CIA-Triade (Fundament)

| Prinzip | Bedeutung | Unsere Umsetzung |
|---|---|---|
| **Confidentiality** | Nur Berechtigte sehen Daten | shop_id Isolation (Structured Keys), JWT Token, HTTPS |
| **Integrity** | Daten nicht unbemerkt veraendert | Checksums, DB-Constraints, Audit-Log (wer hat wann was geaendert) |
| **Availability** | System erreichbar wenn noetig | Triple-Backup, Health-Check, Queue (kein Blockieren), Uptime-Monitoring |

## Sicherheits-Begriffe

### Security (Schutz vor Angriffen)

| Bedrohung | Massnahme | Technisch |
|---|---|---|
| SQL Injection | Keine rohen Queries | SQLAlchemy ORM (parametrisiert) |
| XSS (Script-Injection) | Input sanitieren | Vue.js escaped automatisch, CSP-Header |
| CSRF (gefaelschte Requests) | Token pro Session | CSRF-Token in Forms, SameSite Cookies |
| Brute Force Login | Rate Limiting | Redis Counter: max 5 Versuche/Minute |
| API Missbrauch | Rate Limiting + Auth | API-Key pro T1, Token pro T2/T3 |
| Secret Leaks | Keine Secrets im Code | .env Dateien, gitleaks pre-commit Hook |
| Veraltete Pakete | Dependency Scanning | `pip audit`, Dependabot auf GitHub |

### Safety (System tut keinen Schaden)

| Risiko | Massnahme | Technisch |
|---|---|---|
| Doppelbuchung | Idempotency | Unique Constraint auf (shop_id, date, time, slot) |
| Doppelte Zahlung | Idempotency Key | Stripe Idempotency-Key bei jedem Request |
| Falsche Daten anzeigen | Validierung | Pydantic Models (Type-Check auf jedem Input) |
| Fehler eskaliert | Isolation | Queue pro Entity — ein kaputter Job stoppt nicht alles |
| Ungewollte Loeschung | Soft Delete | `deleted_at` Timestamp statt echtes DELETE |

### Reliability (Stabilitaet ueber Zeit)

| Massnahme | Technisch |
|---|---|
| Automatische Tests | pytest bei jedem Commit (pre-commit Hook) |
| Type Checking | pyright prueft alle Typen |
| Linting | Ruff findet Fehler vor dem Ausfuehren |
| Datenbank-Migrations | Alembic (versionierte Schema-Aenderungen) |
| Monitoring | Health-Check Endpunkt, Sentry fuer Fehler |
| Logging | Strukturierte Logs (JSON), durchsuchbar |

### Resilience (Erholung nach Ausfall)

| Szenario | Massnahme | Technisch |
|---|---|---|
| Server stuerzt ab | Auto-Restart | Systemd/Docker restart policy |
| Datenbank weg | Backup | Triple-Backup (C: + D: + iCloud), taeglich |
| Externer Service down | Retry + Fallback | Celery Retry (3x), Adapter meldet Fehler |
| Netzwerk weg | Queue puffert | Redis Queue speichert Jobs bis Netz zurueck |
| Deployment kaputt | Rollback | Git revert, vorherige Version sofort deploybar |

### Privacy (Datenschutz / PDPO Hong Kong)

| Anforderung | Massnahme | Technisch |
|---|---|---|
| Daten minimieren | Nur speichern was noetig | Schema-Review: jedes Feld hat Grund |
| Einwilligung | Consent vor Datensammlung | Consent-Flag in User-Tabelle |
| Recht auf Loeschung | Account + Daten loeschbar | DELETE /api/me → Soft Delete + 30 Tage Frist |
| Daten-Export | User kann seine Daten holen | GET /api/me/export → JSON Download |
| Verschluesselung | Daten verschluesselt lagern | HTTPS (Transport), Encryption at Rest (DB) |
| Zugriffs-Log | Wer hat was gesehen | Audit-Log Tabelle (user_id, action, timestamp) |

## Frameworks & Standards

### OWASP Top 10 (Web-Schwachstellen)

| # | Schwachstelle | Unser Schutz |
|---|---|---|
| 1 | Broken Access Control | shop_id Check bei JEDEM Request, RBAC (Rollen) |
| 2 | Cryptographic Failures | bcrypt fuer Passwoerter, AES fuer sensitive Daten |
| 3 | Injection | SQLAlchemy ORM, Pydantic Validation |
| 4 | Insecure Design | Threat Modeling bei neuen Features |
| 5 | Security Misconfiguration | .env nicht im Repo, Defaults sicher, CORS strict |
| 6 | Vulnerable Components | gitleaks + pip audit + Dependabot |
| 7 | Auth Failures | JWT mit Expiry, Refresh Tokens, Rate Limiting |
| 8 | Data Integrity Failures | Signierte Tokens, DB-Constraints |
| 9 | Logging Failures | Strukturierte Logs, Audit-Trail |
| 10 | SSRF | Keine User-URLs direkt aufrufen, Allowlist |

### Zero Trust (Vertraue niemandem)

| Prinzip | Umsetzung |
|---|---|
| Pruefe jeden Request | JWT Token wird bei JEDEM API-Call validiert |
| Minimale Rechte | T3 kann nur eigene Buchungen sehen, nicht alle |
| Segmentierung | shop_id Isolation — ein Laden sieht nie einen anderen |
| Verschluessele alles | HTTPS (kein HTTP), Secrets verschluesselt |
| Logge alles | Wer, wann, was — bei jedem Zugriff |

### ISO 27001 (vereinfacht fuer Stufe 1)

| Bereich | Was wir tun |
|---|---|
| Risiko-Bewertung | Einmal pro Quartal: Was kann schiefgehen? |
| Zugriffskontrolle | Rollen (T1/T2/T3), API-Keys, JWT |
| Incident Response | Sentry-Alert → Log pruefen → Fix → Post-Mortem |
| Business Continuity | Triple-Backup, Rollback-Faehigkeit |
| Dokumentation | CLAUDE.md + Tree dokumentiert alle Entscheidungen |

### NIST Cybersecurity Framework

| Phase | Was | Unser Tool |
|---|---|---|
| Identify | Was haben wir, was ist kritisch? | Tree + Health-Check |
| Protect | Schutzmassnahmen einbauen | Auth, Encryption, Validation |
| Detect | Angriffe erkennen | Logging, Sentry, Rate-Limit-Alerts |
| Respond | Auf Vorfall reagieren | Incident-Playbook, Sentry-Notifications |
| Recover | Wiederherstellen | Triple-Backup, Git Rollback |

## Referenz-Architektur: NemoClaw + OpenShell (NVIDIA)

NVIDIA hat mit NemoClaw/OpenShell gezeigt wie man autonome Agents sicher deployed. Relevante Prinzipien fuer uns:

| Prinzip | Herkunft | Unsere Anwendung |
|---|---|---|
| Deny-by-Default | NemoClaw NC1 | T1-Module und API-Keys starten mit null Rechten |
| Privacy Router | NemoClaw NC2 | AI-Calls nach Sensitivitaet routen (lokal vs. Cloud) |
| Deklarative Policy | OpenShell OS1 | Berechtigungen als YAML, nicht hardcoded |
| 4 Schutzdomaenen | OpenShell OS2 | Daten/Netzwerk/Prozess/Inferenz separat isoliert |
| Live Policy Updates | OpenShell OS3 | Module zur Laufzeit an/aus ohne Neustart |
| Full Audit Trail | OpenShell OS4 | Jede Allow/Deny-Entscheidung geloggt |

**Privacy Router fuer AI-Calls (NC2):**
```
Kundendaten/Zahlungen  →  Lokales Modell (kein Cloud-Leak)
Allgemeine Anfragen    →  Cloud-LLM (Claude/GPT, guenstiger)
```
