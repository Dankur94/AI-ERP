# Wayfinding-Modul — Indoor-Navigation fuer 工廈

## Problem

Hong Kong Industrial Buildings (工廈) haben Dutzende kleine Shops pro Gebaeude. Google Maps stoppt am Eingang. Kein bestehender Anbieter loest das Problem guenstig fuer kleine Shops. Dieses Modul schliesst die Luecke.

Ziel: Discovery (welche Shops gibt es hier?) + Wayfinding (wie komme ich hin?) + Live-Position (wo bin ich gerade?)

## Kern-Innovation

T2 beschreibt den Weg zu seinem Shop als **Freitext** (DE/EN/中文). AI parsed den Text in strukturierte Segmente. Daraus wird automatisch eine **Map generiert**. Je mehr Shops sich registrieren, desto vollstaendiger wird die Map.

## Fundamentales Navigations-Modell

Jede Navigation besteht aus 4 Fragen pro Schritt:
1. **Wo bin ich?** → Referenzpunkt (Aufzug, Ecke, Kreuzung)
2. **Wo will ich hin?** → Ziel (Shop Name, Floor, Unit)
3. **Was ist der naechste Schritt?** → Eine klare Anweisung
4. **Erkennungszeichen?** → Etwas Sichtbares das bestaetigt

### Stabile Referenzpunkte (aendern sich NIE)
- Gebaeudestruktur (Gaenge, Ecken, Kreuzungen) — Beton
- Aufzuege / Treppen — tragende Struktur
- WC, Feuerloescher, Notausgaenge — gesetzlich vorgeschrieben

### Referenzpunkt-Typen
| Typ | Kategorie | Zuverlaessigkeit |
|---|---|---|
| Geometrie (links, Ecke, T-Kreuzung) | Raeumlich | Sehr hoch |
| Topologie (einziger Weg, 3 Optionen) | Verbindungen | Sehr hoch |
| Semantik (Ladennamen, Schilder) | Bedeutung | Niedrig (aendert sich!) |

## Graph-Modell

Ein Stockwerk = ein Graph aus Knoten und Kanten.

### Knoten-Typen
| Typ | Symbol | Bedeutung | Stabilitaet |
|---|---|---|---|
| Aufzug | 🛗 | Startpunkt (T3 kommt hier an) | Fix (Betonschacht) |
| Treppe | 🪜 | Alternativer Startpunkt | Fix (tragend) |
| Ecke | ◣ | Richtungswechsel | Fix (Waende) |
| Kreuzung | ✚ | Entscheidungspunkt (4 Wege) | Fix |
| T-Stueck | ⊤ | Entscheidungspunkt (3 Wege) | Fix |
| Sackgasse | ▮ | Ende eines Gangs | Fix |

### Kanten (Gaenge)
- Verbinden zwei Knoten
- Haben: doors_left, doors_right (Tuer-Counts)
- Shops haengen an Kanten: side + position

### Datenstruktur
```
WayfindingPath:
  start:    "lift_a"
  segments: [
    { direction: "straight", doors_left: 3, doors_right: 2 },
    { turn: "right" },
    { direction: "straight", doors_left: 4, doors_right: 0 }
  ]
  target:   { side: "left", door: 3 }
```

## Merge-Algorithmus

Wenn mehrere T2-Shops Wege registrieren, werden ihre Pfade zu einem Gesamt-Graph gemerged.

### Regeln
1. Gleicher Startpunkt + Richtung = gleiche Edge
2. Tuer-Count: Mehrheit gewinnt, bei Gleichstand → hoeherer Wert
3. Node-Typ wird nur UPGRADED, nie downgraded (Ecke → T-Stueck → Kreuzung)
4. Erster Shop definiert Orientierung (links/rechts Referenz)
5. Konflikte → AI fragt gezielt nach (nie still ueberschreiben)
6. Confidence sinkt mit Zeit (Shop antwortet nicht → evtl. weggezogen)

### Confidence-Score
Jede Edge/Node hat: `confidence = f(quellen, uebereinstimmung, alter)`
- 4 Shops bestaetigen gleiche Daten → 0.95
- 1 Ausreisser → markiert, AI fragt nach
- Keine Bestaetigung seit 6 Monaten → Confidence sinkt

### Konflikt-Typen
1. **Tuer-Counts unterschiedlich** → Mehrheit gewinnt, Ausreisser wird gefragt
2. **Topologie-Widerspruch** (Ecke vs. Kreuzung) → Upgrade auf mehr Wege
3. **Richtungs-Ambiguitaet** → Erster Shop = Referenz, AI fragt bei Widerspruch

## Live-Positionierung (Sensor-Fusion)

Alle Sensoren im Browser, $0, keine App noetig.

### Sensoren
| Sensor | Liefert | Web API | Genauigkeit |
|---|---|---|---|
| Barometer | Stockwerk | DeviceMotion | ±1 Stockwerk |
| Accelerometer | Schritt-Zaehlung | DeviceMotion | ±0.5m pro Schritt |
| Gyroskop | Drehrichtung | DeviceOrientation | Driftet |
| WiFi-Scan | Naeherung zu bekannten Punkten | Network Info API (limited) | Gebaeude-Level |

### Graph-Snap (der Clou)
Dead Reckoning (Schritte + Richtung) driftet normalerweise. Aber unser Graph korrigiert:
- Nutzer laeuft 20 Schritte + dreht rechts
- Graph kennt: Ecke_1 ist nach ~12m mit Rechtskurve
- SNAP: Position = Ecke_1, Drift = 0 (Reset!)
- In 工廈 kommt alle 10-20m ein Knoten → Drift baut sich nie auf

### Position Engine Pipeline
```
Barometer ─────► Stockwerk (3/F)        [fest]
Step Counter ──► Distanz (≈15m)         [driftet]
Gyroskop ──────► Richtung (Nord)        [driftet]
Graph-Matching ► Korrektur!             [fixiert Drift]
WiFi Scan ─────► Naeherung              [Bonus]
                    │
                    ▼
            Position: 3/F, Gang 2,
            zwischen Ecke_1 und Kreuzung_1,
            ≈ bei Tuer 3 links
```

## T2 Eingabe-Flow

```
1. T2 tippt Adresse ein
   → Google Maps API holt Gebaeude (Name, Polygon, Place ID)
   → "Ist das dein Gebaeude?" → Ja

2. T2 waehlt: Hochhaus | Compound
   → "Wie viele Stockwerke?"

3. T2 tippt auf Karte: "Hier ist der Eingang"

4. T2 beschreibt den Weg (Freitext, beliebige Sprache)
   → AI parsed → Segmente → Graph
   → Map wird generiert → "Stimmt das?"

5. Fertig. Map ist live.
```

## T3 Navigations-Flow

```
1. T3 sucht Shop in App / klickt Link
2. Sieht: Gebaeude-Info + generierte Floor-Map
3. Tippt "Navigation starten"
4. Waehlt: "Ich bin am Aufzug A, 3/F"
5. Sieht: Map mit Live-Position (blauer Punkt)
6. Laeuft → Position updated → Graph-Snap korrigiert
7. Ankunft → "Du bist da!"
```
