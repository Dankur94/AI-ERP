# T3 Web-App (Endkunde — AI-Chat-First)

## Kernentscheidung (Mai 2026)

T3 ist KEIN klassisches UI mit Buttons und Formularen. T3 ist ein **Chat-Interface mit AI**.
Der Endkunde spricht mit der AI, die AI fuehrt Aktionen aus.

```
Endkunde: "Ich will morgen um 14 Uhr zum Friseur"
AI:       "Bei Tony's Hair? Morgen 14:00 ist frei. Soll ich buchen?"
Endkunde: "Ja"
AI:       → booking.create → Bestaetigung
```

## Warum AI statt UI

| Klassisches UI | AI-Chat-First |
|---|---|
| Nutzer muss Navigation verstehen | Nutzer sagt was er will |
| Formulare ausfuellen | AI fragt nach fehlenden Infos |
| Jeden Flow einzeln bauen | Ein Chat-Interface fuer alles |
| Stufe 4 Vision: "Intent → Result" | Passt perfekt |

## Was der Endkunde erlebt

1. Sieht QR-Code im Laden (an Kasse, Tuer, Tisch)
2. Scannt mit Handy-Kamera
3. Web-App oeffnet sofort (kein Download, kein Login)
4. **Chat-Interface** — Textfeld: "Was moechtest du?"
5. AI antwortet, fuehrt Aktionen aus, fragt bei Bedarf nach

## Fallback: Structured UI

Fuer haeufige Aktionen gibt es **zusaetzlich** Quick-Actions (Buttons):
- "Termin buchen" → oeffnet vereinfachten Chat-Flow
- "Speisekarte" → zeigt Karte direkt an
- "Oeffnungszeiten" → sofortige Antwort ohne AI-Call

Die AI ist der Hauptkanal. Buttons sind Shortcuts, kein Ersatz.

## Sicherheit

T3 darf nur eingeschraenkte Actions ausfuehren. Alles geht durch den **AI Permission Gate**:
- Nur eigene Buchungen sehen/stornieren
- Keine Zugriff auf fremde Daten
- Zahlungen nur mit expliziter Bestaetigung
- Details: siehe Node "AI Permission Gate"

## Anforderungen (unveraendert)

- Laedt in < 1 Sekunde
- Kein App Store
- Kein Konto noetig (fuer erste Nutzung)
- Funktioniert auf jedem Handy (iPhone + Android)
- Mobile-first Design

## Technik

- Vue.js als PWA (Progressive Web App)
- Chat-UI-Komponente (Eingabe + Nachrichten-Verlauf)
- WebSocket-Verbindung zum Gateway fuer Real-Time
- Service Worker fuer Offline-Basics
- Push Notifications nach Opt-in
