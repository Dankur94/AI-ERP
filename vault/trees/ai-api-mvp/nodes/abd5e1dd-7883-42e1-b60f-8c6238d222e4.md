# Datenmodell & Structured Keys (shop_id)

## Kern-Entscheidung

**`shop_id` ist der universelle Sharding-Key.** Alles gehoert immer einem Laden.

## Key-Schema (von OpenClaw OC7)

```
shop:{shop_id}:module:{module_id}:entity:{entity_id}
```

Beispiele:
```
shop:abc123:booking:slot:2024-01-15-14h
shop:abc123:profile:info
shop:abc123:payment:tx:xyz789
shop:abc123:memory:daily:2024-01-15
```

## Was das bedeutet

- Jede Abfrage ist automatisch isoliert (WHERE shop_id = ...)
- Kein Daten-Leak zwischen Laeden moeglich
- Multi-Tenancy faellt gratis raus (wie bei Shopify)
- Spaeter: Sharding pro Shop trivial

## Geteiltes Datenmodell (von Stripe)

Ein Datenmodell fuer alle Module — nicht jedes Modul hat eigene Tabellen fuer User/Shop/etc. Kern-Entities sind zentral:

- `shops` — Laden-Profile
- `users` — Alle Nutzer (T1, T2, T3)
- `modules` — Welcher Laden hat welche Module aktiv
- `events` — Event-Log (fuer Memory + Audit)
