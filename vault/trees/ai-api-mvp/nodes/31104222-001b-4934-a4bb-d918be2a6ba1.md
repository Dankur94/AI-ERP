# 3 — MODULE (Features bauen)

Hier baust du das was Nutzer tatsaechlich verwenden. Jedes Modul ist ein eigenstaendiges Feature.

## Voraussetzung

KERN muss stehen. Ohne Datenmodell, Gateway und Queue kannst du kein Modul sauber bauen.

## Reihenfolge

1. **MVP-Kern** — Das Minimum um einem Laden etwas zu zeigen
2. **Zweite Welle** — Sobald der erste Laden live ist
3. **T1-Module** — Sobald die API stabil ist

## Jedes Modul folgt dem gleichen Muster

1. Eigene Routes unter `/api/v1/shops/{shop_id}/{modul}/`
2. Eigene DB-Tabellen (aber Kern-Entities teilen)
3. Eigener AI-Kontext (modularer Prompt, OC5)
4. Eigene Queue-Topics (`queue:shop:{id}:{modul}`)
5. Kann mit Bridge-Modulen verbunden werden

## Checkliste: Modul fertig?

- [ ] Routes definiert und dokumentiert
- [ ] Tests geschrieben
- [ ] Ueber Gateway erreichbar
- [ ] shop_id Isolation geprueft
- [ ] Event-Log schreibt mit (fuer Memory)
