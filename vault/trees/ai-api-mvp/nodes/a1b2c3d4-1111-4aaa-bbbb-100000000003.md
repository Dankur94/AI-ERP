# Modul-Loop — Wiederkehrender Prozess fuer jedes Feature

## Der Loop

Jedes Modul durchlaeuft dieselben 8 Schritte. Immer. Ohne Ausnahme.

```
     ┌──────────────────────────────────────────┐
     │                                          │
     v                                          │
1. PROBLEM         Was will der Laden?          │
     |                                          │
     v                                          │
2. SCHEMA          Welche Daten braucht es?     │
     |                                          │
     v                                          │
3. API             Welche Endpunkte?            │
     |                                          │
     v                                          │
4. ADAPTER         Braucht es externe Services? │
     |                                          │
     v                                          │
5. QUEUE           Was laeuft im Hintergrund?   │
     |                                          │
     v                                          │
6. TEST            Funktioniert es?             │
     |                                          │
     v                                          │
7. UI              Was sieht T2/T3?             │
     |                                          │
     v                                          │
8. FEEDBACK        Was sagt der Nutzer?         │
     |                                          │
     └──── zurueck zu 1. ──────────────────────┘
```

---

## Beispiel: Booking-Modul fuer Tony

| Schritt | Ergebnis |
|---|---|
| 1. Problem | Tony will Online-Buchung |
| 2. Schema | Booking(shop_id, customer_id, date, time, service, status) |
| 3. API | POST /bookings, GET /bookings/:id, DELETE /bookings/:id |
| 4. Adapter | Google Calendar Sync (optional), Twilio SMS-Bestaetigung |
| 5. Queue | Buchung in Tonys Queue → Bestaetigung senden |
| 6. Test | Buchung anlegen, aendern, stornieren, Doppelbuchung verhindern |
| 7. UI | T3: Kalender-Ansicht. T2: Buchungsliste im Dashboard |
| 8. Feedback | Tony: "Kann man halbe Stunden buchen?" → zurueck zu 1. |

---

## Wichtig

- Iteration 3 (MODULE) ist NICHT einmal durch und fertig
- Der Loop wiederholt sich PRO FEATURE
- Booking = 1x Loop, Payment = 1x Loop, Chat = 1x Loop
- Jeder Loop-Durchlauf produziert: Schema + API + Test + UI
- Das ist die Hauptarbeit die nie aufhoert (neue Features = neue Loops)
