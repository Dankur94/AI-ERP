# Memory 4 Schichten

Von OpenClaw OC6 — ab Tag 1 eingebaut.

## Die 4 Schichten

| # | Schicht | Was | Beispiel |
|---|---|---|---|
| 1 | **Session** | Was gerade passiert | Kunde bucht gerade einen Termin |
| 2 | **Daily Logs** | Was heute passiert ist | 5 Buchungen, 2 Stornierungen |
| 3 | **Long-term** | Zusammengefasste Muster | "Dienstags wenig los, Freitags voll" |
| 4 | **Semantic Search** | Vektordatenbank, Embeddings | "Aehnliche Kunden haben X gebucht" |

## Aufbau-Reihenfolge

1. **Woche 1-2:** Schicht 1 + 2 (trivial, DB-Eintraege)
2. **Woche 3-4:** Schicht 3 (Zusammenfassungs-Jobs)
3. **Ab Monat 2:** Schicht 4 (Embeddings, Vektor-DB)

## Warum von Tag 1

- Daten die nicht erfasst werden, sind verloren
- Je frueher wir sammeln, desto klueger wird die AI
- Das ist unser Burggraben — akkumulierter Kontext pro Laden
- Stufe 4 (Intent → Ergebnis) braucht dieses Wissen

## Konkrete Umsetzung (von OpenClaw OC12)

OpenClaw speichert Memory als **Plain Markdown auf Disk**:
- `memory/YYYY-MM-DD.md` — Tageslog (was heute passiert ist)
- `MEMORY.md` — Langzeit-Fakten (zusammengefasst)

Dahinter laeuft ein **Hybrid-Index** (Fulltext + Vektor-Suche) der automatisch aktualisiert wird.

Fuer uns konkret:
```
shop:{shop_id}/memory/
├── session/           ← Schicht 1: aktive Session-Daten (Redis/DB)
├── daily/
│   ├── 2026-05-06.md  ← Schicht 2: Tageslog als Markdown
│   └── 2026-05-05.md
├── longterm.md        ← Schicht 3: Zusammengefasste Muster
└── index/             ← Schicht 4: Hybrid-Index (FTS5 + Qdrant)
```

**Vorteil Markdown:** Lesbar, debugbar, versionierbar. Kein Lock-in. Schicht 4 ist nur ein Index UEBER die bestehenden Daten — kein separates System.

## Kosten

- Schicht 1-3: ~$0 (SQLite/Postgres + Markdown-Files)
- Schicht 4: ~$10-50/Monat (Embeddings + Vektor-DB)
