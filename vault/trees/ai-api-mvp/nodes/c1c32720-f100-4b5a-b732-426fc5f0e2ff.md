# 7 AI-Readiness-Schichten (T2 + T1)

Die Plattform erledigt alle 7 Schichten — fuer T2 unsichtbar, fuer T1 per API/Klick.

## Uebersicht

| # | Schicht | Fuer T2 (Laden) | Fuer T1 (Entwickler via API) |
|---|---|---|---|
| 1 | Daten-Readiness | Wir strukturieren ihre Daten (Menu, Services, Preise, Zeiten) | Ein Klick: Datenmodell steht, Schema generiert, Endpoints da |
| 2 | API-Readiness | Laeuft im Hintergrund, Laden merkt nichts | Sofort funktionierende API fuer jeden Laden (REST/GraphQL) |
| 3 | Kontext-Readiness | Wir erfassen ihr Wissen (Oeffnungszeiten, Regeln, Specials) | RAG/Knowledge Base pro Laden automatisch befuellt, per API abfragbar |
| 4 | Integration-Readiness | Plattform entscheidet welches AI-Modell | T1 ruft eine API auf, dahinter laeuft das beste Modell automatisch |
| 5 | Governance-Readiness | Wir setzen Regeln (wer darf was sehen/aendern) | Permissions, Scopes, Audit Trails out-of-the-box |
| 6 | Kosten-Readiness | Laden zahlt Flatrate, kein Token-Denken | Dashboard mit Verbrauch, Limits, Budgets — alles fertig |
| 7 | Workflow-Readiness | Wir sagen dem Laden wo AI hilft | T1 waehlt aus fertigen Workflow-Bausteinen (Booking, Chat, Recommend) |

## Zwei Eingaenge ins MVP

1. **Laden-Onboarding (T2):** "Sag mir was du anbietest" → Plattform baut alles auf
2. **Developer-API (T1):** Dokumentation + API-Key → sofort bauen
