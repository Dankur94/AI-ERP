# Modul-Typen

## Drei Typen

| Typ | Wer baut | Woher | Beispiel |
|---|---|---|---|
| **Eigen (orchestriert)** | Wir | Bestehende APIs zusammengebaut | Zahlungen = Stripe im Backend |
| **Eigen (custom)** | Wir, von Hand | Eigenentwicklung | Erste Kunden-Probleme perfekt loesen |
| **Fremd** | T1 Entwickler | Auf unserer Plattform | Spezial-Module fuer Branchen |

## Eigen (orchestriert) — der Normalfall

Fast nichts from scratch. Zusammengebaut aus:
- Stripe (Payments)
- Twilio/Plivo (SMS)
- Firebase FCM (Push)
- Claude API (AI)
- etc.

Wir sind der Klebstoff. Die Wertschoepfung liegt in der Kombination + lokalem Kontext.

## Bridge-Module (von Odoo)

Wenn ein Laden Modul A UND Modul B aktiviert hat, kann ein Bridge-Modul automatisch aktiv werden:
- Booking + Payment → "Bei Buchung direkt bezahlen"
- Chat + Booking → "Per Chat buchen"
- Profil + Bewertungen → "Bewertungen auf Profil anzeigen"

## T1-Module — Regeln

- Laufen in Sandbox (isoliert)
- Zugriff nur ueber offizielle API
- Koennen Plattform nicht kaputt machen
- Werden geprueft bevor sie live gehen

### Sandbox-Modell (von NemoClaw NC1 + OpenShell OS1/OS2)

**Deny-by-Default:** T1-Module starten mit null Rechten. Jede Berechtigung muss explizit erteilt werden.

**4 Schutzdomaenen** (abgeleitet von OpenShell):

| Domaene | T1-Modul darf | T1-Modul darf NICHT |
|---|---|---|
| Daten | Eigene Tabellen lesen/schreiben | Andere Shop-Daten oder Kern-Tabellen |
| Netzwerk | Eigene Webhook-URLs aufrufen | Beliebige externe URLs oder interne Services |
| Queue | Eigene Queue beschicken | Fremde Queues oder Queue-Prioritaeten aendern |
| AI/Inferenz | Eigenen AI-Kontext nutzen | Globale Modell-Config oder andere Module beeinflussen |

**Policy als YAML** (deklarativ, versionierbar):
```yaml
# module-permissions.yaml
module: booking-extended
shop_id: abc123
permissions:
  data: [bookings, customers]
  endpoints: [POST /bookings, GET /bookings/:id]
  webhooks: [https://partner.example/notify]
  queue: booking
```

**Audit Trail:** Jede Allow/Deny-Entscheidung wird geloggt (OS4). Bei Missbrauch: Modul sofort deaktivierbar (OS3 — Live Policy Updates).
