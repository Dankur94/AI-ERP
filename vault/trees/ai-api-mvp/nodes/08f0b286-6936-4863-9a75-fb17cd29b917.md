# Gateway (Hub-and-Spoke, ein Einstieg)

## Was es ist

Ein zentraler Einstiegspunkt fuer ALLES. T1, T2, T3 — alle gehen durch dieselbe Tuer.

```
T1 (API-Call) ──┐
T2 (Dashboard) ─┼──→ [GATEWAY] ──→ Module / Services
T3 (Web-App) ──-┘
```

## Was das Gateway tut

1. **Auth pruefen** — Wer bist du? Was darfst du?
2. **Routing** — Welches Modul ist zustaendig?
3. **Rate Limiting** — Nicht zu viele Anfragen
4. **Logging** — Alles wird protokolliert
5. **Fehlerbehandlung** — Einheitliche Fehlermeldungen

## Warum ein Einstieg

- Vereinfacht Debugging (ein Log, ein Ort)
- Auth nur einmal implementieren
- T1-Entwickler haben eine klare API-Adresse
- Monitoring an einem Punkt

## Technisch (gesetzt: 2026-05-06)

FastAPI als Gateway. Routes pro Modul:
```
/api/v1/shops/{shop_id}/booking/...
/api/v1/shops/{shop_id}/profile/...
/api/v1/shops/{shop_id}/payment/...
/ws/chat                              ← WebSocket fuer AI-Chat (T2/T3)
```

Auth: Custom JWT mit 3 Flows (T1: API Key, T2: JWT, T3: Session Token).
Real-Time: FastAPI WebSocket (eingebaut, kein Socket.IO).
Connection Manager: ~40 Zeilen, 2 Rooms (shop:{id}, session:{id}).

## AI-Routing (gesetzt: 2026-05-06)

T2 und T3 nutzen AI-Chat als **einziges Interface**. Kein klassisches Dashboard/UI.
Das Gateway routet AI-Requests in 2 Stufen:

```
T3/T2 Chat ──→ Gateway ──→ AI Router ──→ Permission Gate ──→ Modul
                              │                │
                              │                └─ policies/t3.yaml
                              │                   policies/t2.yaml
                              │
                              ├─ Einfach (90%) → Claude Haiku
                              └─ Komplex (10%) → Claude Sonnet
                                 Fallback      → OpenAI GPT-4o
```

Kein Pattern-Match (zu fehleranfaellig). Immer AI, aber das richtige Model.
Haiku eskaliert selbst zu Sonnet wenn ueberfordert ([ESCALATE]).

Neue Gateway-Komponenten:
- `ai_router.py` — Routet zum richtigen Model (Haiku/Sonnet/Fallback)
- `permission_gate.py` — Prueft ob der Intent fuer diese Rolle erlaubt ist
- `intent_registry.py` — Whitelist aller gueltigen Intents (AI kann nichts erfinden)
- `ws_manager.py` — WebSocket Connection Manager (connect, disconnect, send_to_shop)

## Gateway als Daemon (von OpenClaw OC13)

OpenClaw's Gateway laeuft als **dauerhafter Hintergrund-Dienst** (Daemon), nicht als Request-Response-Server der bei jeder Anfrage startet. Clients (T1/T2/T3) verbinden und trennen sich, der Gateway bleibt immer aktiv.

Fuer uns:
- Gateway laeuft via **systemd** (Linux) oder **Docker** (Container) — Auto-Restart bei Crash
- **WebSocket-Verbindung** fuer Real-Time (Buchungsbestaetigung, Live-Updates) lebt IM Gateway
- Health-Check pollt den Daemon regelmaessig
- Ein Prozess, alle Channels (REST + WebSocket + zukuenftig WhatsApp-Bot)
